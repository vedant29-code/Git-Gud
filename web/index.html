The Reality Check

Why Linters Aren't Enough

Linters verify syntax rules and semicolons. They have no idea your function does five contradictory things or that your "temporary" hardcoded secret will survive into production.

🔍

Syntax vs Semantic Logic

Flake8 or ESLint celebrate valid syntax while completely missing catastrophic architectural smells like eval() on raw user requests.

LINTER: "No PEP8 violations. Looks good!"
REALITY: Arbitrary remote code execution flaw.
💣

The Silent Sins

Bare except: pass clauses, debug prints, and SQL concatenation in string templates pass standard builds silently until customer data is gone.

LINTER: "Type checks passed (0 errors)."
REALITY: Swallows SIGTERM & creates zombie jobs.
😴

Reviewer Fatigue

Human reviewers get tired scanning 400-line PRs on Friday afternoon. Git-Gud AI reviews in 2 seconds right at commit time, before your diff ever pollutes Git history.

PR REVIEW: "LGTM! 👍" (Merged without reading)
REALITY: Pushed 9 console.logs & active debugger.

Architecture & Flow

How It Works in 4 Steps

A zero-overhead pipeline that hooks directly into native Git mechanics without altering your existing tooling.

01
⚡

Trigger Commit

You run standard git commands. The native POSIX hook intercepts execution prior to commit object creation.

git commit -m "feat: login"
02
🧹

Diff Budgeting

Git-Gud extracts the staged diff, silently ignores lockfiles and binaries, and budgets tokens to stay fast.

git diff --cached (budget: 12KB)
03
🧠

Local LLM Review

Your local Ollama daemon parses the diff in an isolated untrusted sandbox with zero internet exposure.

POST localhost:11434/api/generate
04
⚖️

Pass or Block

Clean code passes seamlessly. Defects under threshold block the commit with actionable fixes and roasts.

Exit 0 (Pass) | Exit 1 (Block)
Engineered for Devs

Key Capabilities

Built from scratch to be non-intrusive, lightning fast, and strictly local.

SECURITY & PRIVACY

100% Local & Private

Direct communication with localhost:11434 via Python standard library urllib. Zero analytics, zero cloud tokens, your proprietary code never leaves your workstation.

ERGONOMICS

Zero pip Dependencies

100% pure Python standard library. No virtualenv activation required, no conflicting wheel versions, and zero vulnerability surface from third-party packages.

RELIABILITY

Fail-Open Safety Policy

If Ollama is offline, times out, or runs out of RAM, Git-Gud AI logs a warning and allows the commit (exit 0). It will never paralyze your team's development velocity.

INTELLIGENCE

Semantic Defect Detection

Identifies bare except blocks, unescaped queries, memory leaks, and SRP violations that static linters are fundamentally blind to.

HARDENED

Prompt Injection Defense

Diffs are isolated inside strict <UNTRUSTED_GIT_DIFF> XML fences. The model is specifically primed to disregard adversarial injection comments in code.

CUSTOMIZABLE

3 Configurable Roast Levels

Choose between Mild (polite, direct suggestions), Spicy (clever sarcasm), or Savage (unapologetic brutality).

Installation & Setup

Get your pre-commit judge operational in a few quick terminal commands.

Step 1: Ensure Ollama is installed and pull the recommended 3B model:

Terminal (Ollama Setup) 
ollama pull phi3

Step 2: Clone Git-Gud AI into your workspace and install into your repo:

Terminal (Repository Installation) 
git clone https://github.com/vedant29-code/Git-Gud.git
cd Git-Gud
./install.sh /path/to/your/project-repo

Step 3: Stage files and commit as usual:

Terminal (Commit) 
git add .
git commit -m "feat: add user authentication"

Install Git-Gud AI globally across all Git repositories on your system using Git's core.hooksPath:

Terminal (Global Hook) 
./install.sh --global

Note: Pre-existing hooks are automatically backed up as pre-commit.legacy and executed first.

Doing an emergency hotfix or in a rush? Git-Gud AI respects native bypass mechanisms:

Method 1: Native Git Flag 
git commit --no-verify -m "hotfix: critical production hotfix"
Method 2: Environment Variable 
GITGUD_SKIP=1 git commit -m "wip: rapid exploratory work"

Configuration Options

Configure Git-Gud AI via a repo-level .gitgud file, git config, or environment variables.

Option Env Variable .gitgud Key Default Description
Model GITGUD_MODEL model phi3 Target Ollama model name (e.g., phi3, llama3.2:3b)
Host GITGUD_HOST host http://localhost:11434 Local Ollama HTTP endpoint
Roast Level GITGUD_ROAST_LEVEL roast_level spicy Intensity: mild, spicy, or savage
Threshold GITGUD_THRESHOLD threshold 6.0 Minimum health score (0–10) required to allow commit
Timeout GITGUD_TIMEOUT timeout 60 Generation timeout in seconds before failing open
Max Diff Chars GITGUD_MAX_DIFF_CHARS max_diff_chars 12000 Character budget limit for staged diff truncation
Strict Mode GITGUD_STRICT strict false If true, fails-closed on Ollama connection errors
⚠️

Honest Limitations & Disclaimers

  • ■
    Lightweight Models (3B–4B) Can Hallucinate: Models like phi3 or llama3.2:3b are optimized for speed and low RAM usage. They occasionally report non-existent line numbers or misinterpret complex meta-programming.
  • ■
    A Nudge, Not a Replacement for CI or Humans: Git-Gud AI is an interactive local coach. It does not replace automated integration test suites, static type checkers (mypy/tsc), or human peer code review.
  • ■
    Diff Truncation Budget: To keep latency under 3 seconds, massive diffs exceeding 12,000 characters are intelligently truncated, prioritizing modified application logic over config.
